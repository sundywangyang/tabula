## 结论与基线

当前项目是可运行的 Windows 文件管理应用，核心浏览、标签与分屏、文件操作、搜索、预览和新增文件工具已有实际实现及回归覆盖。它尚不能按 README 原来的 P0–P8 全部完成来描述：插件系统存在可复现缺陷，跨应用文件剪贴板未接通，当前提交的发布、跨平台和部分系统集成尚未验收。

核查基线为 `master / d76f7c8`，版本 `0.1.0`。本次开始时跟踪文件无未提交修改，已有未跟踪目录 `openspec/` 保持原样。前一份设计文档计划引用的 `62d917d / 327 项测试` 已被新提交取代，不能作为当前进度基线。

本次核查不修改产品实现，不将问题复现记作功能修复。README 已按以下证据校正；历史核查与实现报告保留。

## 已确认需要校正的进度声明

### 插件系统不能标为完成

- **按命令激活未接通**：创建只声明 `onCommand:audit.lazy` 的插件，启动后调用该命令，正式构建返回 `Command not found`。宿主直接转发调用，没有先按事件激活。
- **禁用后重新启用失效**：启动插件命令首次调用成功；禁用、启用均返回成功后，再调命令仍返回 `Command not found`。`disable()` 已移除激活状态，而 `enable()` 只在“仍处于激活状态”时调用激活，条件不匹配。
- **独立进程不构成权限隔离**：核查插件可直接 `require('node:fs')`，读取其扩展目录之外的临时文件。README 原称“扩展无法直接访问系统”与实际运行不符。
- `onFileSystem` 只有事件匹配代码，没有调用入口；预览器注册表、扩展配置、视图、快捷键等声明不代表相应产品流程已经接通。公共扩展包导出的 API 仍为占位，实际可用 API 来自注入的 `context`。
- 当前打包规则只列入 `out`、package.json 和图标，没有把内置 `extensions/` 放入生产发现位置；发布包内的示例扩展可用性仍需补齐并验证。

### 部分用户界面能力与公共桥接并不等价

renderer 的 Zustand 布局实现了真实标签与分屏；但 `tabs.*`、`panes.*` 对应主进程接口仍返回 `null` / `[]`。本轮同时确认“界面存在文件列表”和“桥接布局返回 null”。设计文档应说明当前状态归 renderer 管理，不能据类型定义宣称主进程布局服务已实现。

各窗口运行时状态独立，但都写入同一 `layoutV1`，尚无按窗口划分的会话恢复。复制 / 剪切状态同样保存在当前 renderer 内存中，系统只收到路径文本；不能描述成与系统原生文件剪贴板完整互通。

### 预览、性能和发布不能合并成一个完成状态

预览组件对二进制文件调用整文件 `readFile()`，文本也先读取再截断显示；模块懒加载、列表虚拟化和内容流式读取是不同能力。README 的“大文件全部按需加载”已改为实际读取策略。

已有性能采样入口，但本轮没有进行大目录、超大文件、长时间运行、峰值内存或启动耗时门槛验收。旧 Windows 安装包的文件时间为 2026-06-15，与本次 2026-10-28 核查基线不同；没有重建与安装证据前，只能记为历史产物。macOS / Linux 有 Provider 和构建目标，尚无本轮目标系统运行证据。

### 系统回收站仍有需要单独验证的异常路径

Windows 回收站枚举异常时，Provider 当前记录警告后返回“成功的空列表”。静态检查已确认该行为，本轮没有读取、还原或清空用户真实回收站；不能将空列表直接视为系统回收站验收成功。该问题应与原生文件剪贴板、外部拖拽一起列入系统互通复核。
